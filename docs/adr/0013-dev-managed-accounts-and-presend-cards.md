# ADR 0013: managed DEV accounts and premium cards before delivery

Date: 11 November 2026. Status: accepted for the owner-requested DEV extension; external provider configuration and production gates remain separate.

Use Supabase Auth for customer email/password, verified email, Google and Apple. Credentials stay with that managed provider; the app never stores customer password hashes. Link customers by pinned provider issuer and subject, never by matching email or browser roles. Existing operator credentials do not become public customer accounts. Keep existing DEV SQLite content and encryption key; the production PostgreSQL work in ADR 0001/0005 and #64 stays open.

The adapter needs the existing opaque HttpOnly host-session cookie plus a minimal encrypted token bridge for managed refresh/revocation. New auth_subjects/auth_sessions/auth_flows tables hold identity mapping, encrypted provider tokens and bounded single-use PKCE transactions. Verify users server-to-server, require verified email, revalidate sessions, rotate local login cookies, and apply same-origin/CSRF and rate limits. OAuth uses S256 PKCE with an encrypted server verifier, expiring browser-bound state and fixed return origins. Provider configuration/keys stay on the server. Signup adopts a valid current anonymous workspace only for a new identity; never merge customers by email. Existing-account login cannot silently replace a different temporary workspace containing events.

Premium card selection happens while composing. Six premium editions share the existing fixed $4.99 sandbox price. Cards-owned drafts persist the selected content and edition privately. Billing purchases reference that draft's existing stable card ID. Paid access is still granted only after verified Stripe state. A separate guest-authorized Send operation checks active entitlement, invitation/guest scope, contribution window and switches atomically, then makes the card visible. Cancel/failure/return URLs cannot deliver a draft. Basic cards remain directly sendable; existing accepted cards, orders, gift records and refunds keep their IDs. Full refunds remove premium treatment but preserve delivered words. Drafts are excluded from host inbox, books, moderation and gift attachment.

Animation speed is allowlisted and stored with the existing design document (standard/slow/very slow); slow is the default. Whole-template gallery previews use page scrolling. Motion remains finite, stoppable, static for reduced motion/print, and decorative art stays separate from editable words.

The existing bounded, moderated artwork pipeline is reused with Worker-supported manual redirect handling, a pinned image model, shared quotas and no automatic paid retry. Provider keys must be installed by the owner; fixture tests are not a claim of a real account or image-generation request. TEST/PROD, live payments and database recovery acceptance are unchanged. Keep implementation stories OPEN/In Progress for the owner's manual review.
