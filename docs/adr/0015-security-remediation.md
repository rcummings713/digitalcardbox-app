# ADR 0015: security hardening of the existing review adapters

Date: 15 November 2026. Status: accepted for the current local/DEV application; production gates remain open.

The owner requested implementation, commit and push of the confirmed defects in the [production security assessment](../security/PRODUCTION_SECURITY_ASSESSMENT_2026-11-15.md). This decision fixes those defects without promoting the isolated SQLite/Durable Object adapter to a production stack or enabling live payments. ADRs 0001/0005 and existing foundation stories continue to own that work.

Sensitive operations require a server-recorded interactive authentication less than fifteen minutes old. Migration 008 adds a nullable timestamp to host sessions without changing accepted content or encryption keys. Existing sessions retain ordinary access and must confirm their password before publishing, saving/disabling a gift destination, or retrieving a private export. Provider token refresh and OAuth SSO callbacks do not renew freshness. Same-subject password confirmation validates the current session's CSRF and preserves its opaque cookie, expiry and CSRF value. The UI preserves the open form while confirming and retries the denied request once. DEV seeded/review-session creation retains its explicitly temporary behavior. OAuth customers can use the managed password-recovery flow to set a TheDigitalCardBox password; never request their Google/Apple password. True provider MFA/step-up and production operator MFA remain separate gates.

Events owns lifecycle rules. The first accepted card or created gift intent locks date/type/timezone in the same transaction. An idempotent adapter repair locks existing gift-first events at the earliest recorded gift, preserving their current configuration and records. Closed/paused invitation landings contain only safe presentation fields and create no guest sessions; their invitation artwork is unavailable. Scheduled save-the-date details remain available, while payment identifiers are disclosed only when the event and gifts switch permit handoffs.

Event-bound designs are never written to public device drafts. Anonymous designs use validated seven-day localStorage envelopes. Signed-in standalone designs use validated account-bound sessionStorage, allowing same-tab reload while clearing on sign-out or account changes. Legacy global drafts are discarded because their provenance cannot distinguish private event text. Session changes clear other tabs' private views and drafts; failed authentication during background refresh clears stale private state. This does not revoke an exported file already saved by its owner.

Studio admission counts unexpired sessions. Expired sessions without artwork/job references are pruned; referenced sessions/artwork are retained and do not consume active capacity. This cleanup is not a general data-retention policy.

Workspace reads have stable bounded pages, totals and independent continuation cursors. The UI aggregates complete pages before replacing state and rejects inconsistent totals. Free CardVault exports independently retrieve all eligible event cards through authorized, recent-authenticated, audited pages. Encrypted five-minute continuation tokens bind the host/event/revision; changes, expiry and tampering reject the export before a complete download is reported. Existing free archive format is retained. Production private-object exports, signed downloads and broad retention remain with #49/#56 and PostgreSQL foundations.

Static `_headers` and the DEV Worker apply CSP, referrer/nosniff/permissions and HSTS policies, without `includeSubDomains` or preload. The patched Wrangler version is pinned consistently in npm and CI. CI audits dependencies and uses a commit-pinned maintained Gitleaks action with PR comments/artifact upload disabled. Four exact historical fingerprints are excluded only after confirming they are sample invitation tokens or a synthetic request ID; new fixtures/files remain scanned.

Regression evidence and remaining production gates are recorded in the [remediation record](../security/SECURITY_REMEDIATION_2026-11-15.md). No TEST/PROD deployment, external key setup, managed PostgreSQL installation, retention approval, live checkout or backup drill is implied by these changes.
